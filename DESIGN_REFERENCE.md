# 1. PURPOSE

This document translates the visual principles of the reference website into an original design system for Zahid Hasan.

The objective is NOT to duplicate the website.

The objective is to understand WHY the reference feels premium and reproduce those principles through original implementation.

---

# 2. REFERENCE EXPERIENCE

The reference establishes a strong narrative rather than presenting a conventional résumé.

Its visible information architecture includes:

- introduction
- professional evolution
- development/code language
- contact invitation
- selected work

The reference uses very few conceptual sections but extracts a large amount of visual impact from:

- typography
- spacing
- pacing
- movement
- interaction
- project transitions

This principle is important.

DO NOT compensate for weak design by adding more sections.

---

# 3. VISUAL CHARACTER

Target characteristics:

- editorial
- minimal
- confident
- playful but professional
- technical
- personal
- sophisticated
- spacious
- expressive
- interactive

The site should feel intentionally designed rather than assembled from components.

---

# 4. TYPOGRAPHY

Typography is one of the primary visual tools.

Requirements:

- large headlines
- expressive scale differences
- strong hierarchy
- carefully controlled line lengths
- high-quality font rendering
- fluid typography
- intentional whitespace

Avoid:

- excessive font weights
- too many fonts
- tiny headings
- conventional dashboard typography

Recommended strategy:

One primary display typeface.

One supporting UI/body typeface only if necessary.

Use font variation and scale to create hierarchy rather than adding many font families.

---

# 5. LAYOUT

The layout should have strong editorial composition.

Use:

- large margins
- asymmetrical composition
- strong grid
- intentional empty space
- oversized typography
- occasional full-width elements
- controlled overlaps

Avoid:

- every section inside a centered card
- excessive max-width containers
- repetitive 3-column grids
- generic SaaS layouts

---

# 6. HERO

The hero should not be a traditional:

Hello
I'm Zahid
Software Engineer
Button

Instead:

Create a visual introduction.

The visitor should immediately understand:

WHO

Zahid Hasan

WHAT

Software Engineer

VALUE

Builds modern digital products and experiences.

The hero should feel like an opening scene.

---

# 7. STORYTELLING

Professional information should unfold gradually.

Possible structure:

Opening identity

↓

Engineering background

↓

What Zahid builds

↓

How Zahid thinks

↓

Selected work

↓

Contact

The experience should feel like a story rather than a résumé.

---

# 8. CODE VISUAL LANGUAGE

Use code-inspired elements carefully.

Good:

- real snippets from actual projects
- syntax-inspired typography
- implementation details
- technical concepts
- interactive code moments

Bad:

- fake terminal
- random code
- meaningless "010101"
- fake hacker aesthetic

Technical visuals should feel authentic.

---

# 9. PROJECTS

Projects should feel like featured stories.

Each project may use:

- oversized project title
- large image/video
- scrolling reveal
- metadata
- role
- technologies
- interactive preview
- case-study transition

The visual presentation should be more important than a grid of cards.

---

# 10. INTERACTION

Interactions should be discoverable.

Potential interactions:

- magnetic links
- cursor transformation
- project hover preview
- image displacement
- typography movement
- scroll-linked scale
- horizontal project movement
- text masking
- shared-element transitions

Every interaction must have a reason.

---

# 11. MOTION

Motion should feel:

- smooth
- weighted
- deliberate
- continuous

Avoid:

"fade in when visible"

as the default animation for every section.

Prefer choreography.

Example:

A headline may:

1. enter through clipping
2. move into position
3. subtly respond to scroll
4. interact with cursor
5. transition into the next section

---

# 12. COLOR

Use a restrained palette.

Default direction:

- near-black
- off-white
- neutral gray
- one restrained accent

Do not create a rainbow interface.

Accent color should be used strategically.

---

# 13. IMAGERY

Use real project imagery.

Prioritize:

- project screenshots
- product interfaces
- subtle video loops
- carefully cropped UI
- high-resolution assets

Avoid stock photography unless it is genuinely part of a project.

---

# 14. NAVIGATION

Navigation should be minimal.

Possible:

- logo/name
- Work
- About
- Contact

Navigation should not consume attention.

It should feel integrated into the visual composition.

---

# 15. CONTACT

The contact section should feel like the natural ending of the narrative.

Not:

"Have questions? Contact me."

Instead:

A strong personal invitation.

The final CTA should feel like the climax of the page.

---

# 16. MOBILE

Mobile is a separate composition.

Do not merely reduce desktop.

Use:

- simplified interactions
- touch-first interactions
- appropriate typography
- carefully controlled animation
- no desktop cursor
- optimized media

---

# 17. QUALITY TEST

At any point ask:

Does this feel like:

A premium digital portfolio?

OR:

A normal developer portfolio with animations?

Only the first answer is acceptable.
